## Runtime Call Path

1. `configs/exp07_fanout.yaml` supplies `fanouts`; `run_batch.exp07()` passes
   each value to `run_single(..., fanout=value)`. Exp08 and Exp09 pass `None`.
2. `run_batch.run_single()` constructs `GossipStrategy(fanout=fanout)` and a
   `Simulator` with no AHBN controller for standalone Gossip.
3. `Simulator.inject_message()` schedules a `receive` event containing
   `src_id`; `Simulator.run()` dispatches it to `handle_receive()`.
4. On first reception, `Simulator.handle_receive()` passes `src_id` as
   `exclude_target_id` to standalone `GossipStrategy.select_targets()`.
5. `GossipStrategy.select_targets()` builds active physical-neighbor
   candidates, excluding the node and immediate sender. A configured fanout
   samples up to that bound; `None` returns every eligible candidate.
6. `Simulator.handle_receive()` de-duplicates only the returned target list,
   calls `send_message()`, and `send_message()` schedules receive events with
   link delay. Existing first-seen/duplicate accounting is unchanged.

## Findings Before Repair

1. `GossipStrategy` always sampled at most a fixed integer fanout, default 3.
2. `run_single()` converted an omitted fanout to 3, constraining Exp08.
3. Exp09 explicitly passed global fanout 4 to every strategy, constraining
   Gossip and leaking an experiment field beyond Gossip.
4. The receive event retained `src_id`, and Gossip supported
   `exclude_target_id`, but `Simulator.handle_receive()` passed the sender only
   to AHBN. Standalone Gossip could therefore immediately send back to it.
5. Duplicate reception accounting was independent of target selection and did
   not require repair.

## Repairs Performed

- Made standalone Gossip fanout optional: integer means bounded Exp07 sampling;
  `None` means all eligible neighbors for Exp08/09.
- Passed the receive event's immediate `src_id` into standalone Gossip before
  fanout application.
- Kept Exp07's explicit integer sweep unchanged.
- Removed Exp09's legacy global fanout and passed `None` through its construction
  and result-label path.
- Updated `run_one.py` and the Exp08 construction validator to the same normal
  Gossip semantics.
- Added a deterministic targeted S0 probe. No dissemination mechanisms,
  duplicate suppression, AHBN changes, Structured changes, or DC-SoC changes
  were introduced.
