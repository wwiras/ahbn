## Evidence Reconciliation

For each comparator, the validator established:

- **Message origin:** `message_source_id`, the metrics record's `source_id`, and
  the source's first-seen event all equal the configured/effective source; the
  source event is at simulation time `0.0`. DC-SoC additionally asserts the
  source equals `get_dcsoc_master(nodes)`.
- **Forwarding and sender exclusion:** at least one production receive event was
  scheduled, and every non-origin first reception's immediately produced
  target set excludes its sender.
- **Delivery accounting:** the reported ratio equals
  `len(unique first-seen node IDs) / len(active intended node IDs)`.
- **Duplicate accounting:** the reported duplicate count equals the independent
  trace of receive events whose destination had already seen the message. Zero
  duplicates for Structured and DC-SoC are supported by zero traced repeated
  receptions, not assumed from the metric value.
- **Total-forward accounting:** the reported count equals the independent trace
  of successful production receive-event scheduling by `send_message()`.
- **Propagation delay:** the reported value equals the maximum production
  first-seen event timestamp minus the message's simulation-clock creation
  timestamp.
- **Deterministic topology:** two fresh BA constructions using `n=8`, `m=2`, and
  seed `42` produce the identical normalized sorted physical edge list shown
  above for every comparator.
