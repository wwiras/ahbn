# v0.61 S3 Exp08 Workflow Repair

## Reason for the initial stop

The first S3 E0 audit correctly stopped before authoritative execution. The
checked-in Exp08 validators referenced v0.6 paths, old timestamped datasets,
obsolete capped DC-SoC assertions, and the superseded destination-CH overload
model. The existing raw result schema also lacked sufficient run-level evidence
for topology pairing and DC-SoC source/target eligibility.

The previous `docs/stage4_exp08.md` is historical/superseded evidence and is
not the authoritative v0.61 Exp08 record.

## Workflow-only corrections

- `run_batch.py`: records a deterministic pre-overlay physical-topology hash
  and existing runtime source/role/target metadata; writes synchronized,
  timestamped result, evidence, and AHBN trace artifacts plus a current manifest.
- `ahbn/utils.py`: adds an Exp08-only observational evidence row and CSV writer.
- `scripts/inspect_exp08_e0.py`: now resolves v0.61 locally and validates the
  current frozen comparator contract.
- `scripts/validate_exp08_e1.py`: now tests current forwarding-pressure semantics
  with non-authoritative deterministic runs.
- `scripts/validate_exp08_e6.py`: accepts explicit new result/trace paths and
  has no historical timestamp dependency.
- `scripts/validate_exp08_s3_workflow.py`: adds the required EXP08-01 through
  EXP08-15 pre-execution regression gate.

The evidence schema records strategy, seed, factor, physical topology identity,
configured/effective source, DC-SoC Master, eligible existing Core set, selected
target and role, plus maximum structural obligations. Serialization makes no
random calls and is not consumed by dissemination policy.
