Determinations:

1. Base/link delay is calculated in `Simulator.send_message` as `base_delay + uniform(0, jitter)`.
2. The Exp08 overload increment is `base_delay * max(0, ch_overload_factor - 1)`.
3. This increment is an overloaded-node processing/forwarding cost carried in the scheduled receive time, distinct from the base link delay and jitter.
4. The source escaped because the DC-SoC condition tested the destination ID. A Master/source originates the message and never receives it first.
5. The minimum correction was to move the DC-SoC selected-node predicate from `dst` to `src` while retaining the single existing increment.

Structured Exp08 uses the separate `else` path, `apply_ch_overload = dst.is_cluster_head`. That path was not changed. Gossip and AHBN strategy algorithms were not changed.

### Original failure

The original evidence above remains unchanged:

```text
factor=1.0 master=4 target=4 source=4 delivery=1.0 delay=1.0 forwards=19 duplicates=0
factor=3.0 master=4 target=4 source=4 delivery=1.0 delay=1.0 forwards=19 duplicates=0
```

### Root cause

DC-SoC Exp08 tested `dst.node_id == dcsoc_overload_target_id`. When the selected existing Core was also the Master/source, no incoming send targeted it, so no overload term was scheduled. The defect was in shared simulator timing placement, not clustering, role selection, or dissemination.

### Minimum repair

The only production-code change was:

```diff
- apply_ch_overload = dst.node_id == self.dcsoc_overload_target_id
+ apply_ch_overload = src.node_id == self.dcsoc_overload_target_id
```

Affected file: `ahbn/simulator.py`.

### Why the repair is scientifically correct

The selected legitimate Master/Core now incurs processing/forwarding pressure when it forwards. A non-source Core pays the cost after receiving and when forwarding; a Master pays it on originating outgoing dissemination. Link delay and jitter remain separate and unchanged. Roles, source, target relationships, and forwarding counts are unchanged.

### Double-counting check

For DC-SoC Exp08, the condition was moved rather than copied. There is only one selected-target overload predicate and one factor increment. Destination-side selected-target charging is no longer retained for DC-SoC. The distinct generic `dst.is_overloaded` runtime-failure mechanism was untouched and is disabled in these Exp08 checks.
